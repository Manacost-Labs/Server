# Подготовка контекста, память и TypeSafe

Сохранённые [решения об экономии и дешёвых моделях](TOKEN-ECONOMY-DECISIONS.md)
и [каталог рассмотренных инструментов](TOKEN-ECONOMY-TOOLS.md), 2026-09-21.
Работающий [OpenRouter assist для JEV и Gemma](REMOTE-ASSIST.md): контекст,
черновики памяти/документации и вспомогательные оценки выбранных материалов.

Локальная надстройка над существующими RTK, ObservationPack, `context-budget`
и `codex-context`. Требуется Python 3.11+ с SQLite FTS5. Настройка CLI проверена на Linux;
`tiktoken` необязателен для budget gate.
Установка зависимостей, изменение глобальных профилей и запуск моделей
автоматически не выполняются. Все команды вызываются явно.

## Быстрый запуск

В примерах `CHECKOUT` — checkout репозитория skills, `PROJECT` — целевой проект.
Все пути `--task`, `--source`, `--required`, `--file` отсчитываются от PROJECT.

```bash
CHECKOUT=/absolute/path/to/skills
PROJECT=/absolute/path/to/project
ECONOMY="$CHECKOUT/integrations/codex/subscription-savings/context_economy.py"
python3 "$ECONOMY" --project "$PROJECT" --help
```

Данные по умолчанию сохраняются в
`~/.local/state/codex-context-economy/<hash-of-absolute-project-path>/`.
Другой каталог задаётся глобальным `--state-dir PATH` перед подкомандой.
Checkout/worktree с другим абсолютным путём получает отдельную память.
База и логи приватны для текущего пользователя; инструмент не защищает от
злоумышленника с тем же UID. Автоматического удаления записей и логов нет.

## 1. Измерить исходный расход

Скопируйте `examples/attempt.json` в проект и заполните фактические показатели.
Не импортируйте шаблон как проведённый эксперимент. Один файл — одна попытка;
повторяющийся `attempt_id` отклоняется. `dataset` должен идентифицировать одну
версию набора задач, исходного кода и условий сравнения.

```bash
python3 "$ECONOMY" --project "$PROJECT" record --file measurements/attempt.json
python3 "$ECONOMY" --project "$PROJECT" report
python3 "$ECONOMY" --project "$PROJECT" report --end-to-end
```

Варианты: `baseline`, `local`, `typesafe`. Обычный отчёт разделяет модели,
глубину рассуждений и скорость. `--end-to-end` суммирует подготовку и решение
всех моделей внутри одного dataset/variant. `success` означает, что именно
эта попытка достигла критериев задачи; подготовка без завершённой задачи — false.
Все неудачные попытки входят в числитель расхода на завершённую задачу.
`task_id` должен оставаться одинаковым для подготовки, исправлений и решения.

Неизвестные значения остаются null. `input_tokens` включает кешированный вход,
`output_tokens` включает reasoning; эти подмножества не прибавляются повторно.
`api_cost_usd` — стоимость моделей Codex через API, `typesafe_cost_usd` — отдельно
TypeSafe; введите 0 только для подтверждённого отсутствия соответствующего расхода.
Подписочные кредиты и предполагаемые проценты экономии не выдаются за API USD.
Отчёт не читает сессии, ключи или биллинг автоматически и не выдумывает недоступную
телеметрию. Сопоставляйте одинаковые `task_ids`, число завершений и настройки.

## 2. Компактный вывод команд

```bash
python3 "$ECONOMY" --project "$PROJECT" gate --timeout 120 -- python3 -m unittest
```

Команда запускается без shell, с закрытым stdin, в PROJECT. Полные объединённые
stdout/stderr сохраняются в отдельный приватный лог. JSON-квитанция содержит
код завершения, размер, начало, образец диагностик и конец лога. Код завершения
CLI совпадает с исходной командой; тайм-аут возвращает 124 и завершает её группу.
Preview ограничен по размеру и эвристический: он не гарантирует показ каждой
ошибки: просматриваются только первые и последние 64 KiB. Полный лог — источник
истины. Не используйте для интерактивных команд. Команда внутри gate сохраняет
свои возможности, включая сеть; gate не является песочницей.
Лог сохраняется полностью, без ограничения объёма: следите за свободным диском.
Не сохраняйте вывод команд с секретами. RTK можно передать как запускаемую команду;
тогда лог содержит точный вывод RTK, а не скрытый им исходный вывод.
ObservationPack продолжает обслуживать ответы остальных инструментов отдельно.

## 3. Пакет задачи

Создайте task.json по `examples/context-task.json`:
`goal` — строка, `criteria` — непустой список, `constraints` — список.
Все переданные поля задачи сохраняются как обязательные.

```bash
python3 "$ECONOMY" --project "$PROJECT" pack \
  --task task.json --source src/example.py:10:60 --required decisions.md \
  --budget 12000 --check-budget > /tmp/context-package.json
```

Только явно выбранные источники: до 50 файлов, до 1 MiB UTF-8 каждый, без
симлинков, выхода из проекта и известных чувствительных путей. Диапазон строк
не обходит лимит чтения файла. AGENTS.md в корне и вдоль выбранных путей
автоматически включаются целиком. Родительские, системные и клиентские правила
остаются ответственностью активного агента; CLI их не сканирует.

Сначала обязательные данные, затем необязательные источники в указанном порядке,
затем память. Фрагменты не обрезаются посередине. Исключённые источники явно
перечисляются; если обязательные данные с индексом источников не помещаются,
команда завершается ошибкой. Размер по умолчанию — консервативная оценка UTF-8 bytes + 15%,
не реальные токены Astra. `--check-budget` дополнительно вызывает `context-budget`;
совместимый tokenizer применяется только для точно известных моделей.
При ошибке проверки пакет не выводится. Метаданные идут в stderr, пакет в stdout.

Для передачи Astra используйте существующий ручной gate:

```bash
codex-run astra --reason 'Review the bounded implementation decision' \
  --package /tmp/context-package.json minimal \
  'Read /tmp/context-package.json and complete the stated task.'
```

`--package` в существующем launcher проверяет размер; он сам не вставляет
содержимое в prompt. Поэтому чтение файла явно указано в задании.
Этот пример начинает отдельный запуск только по выбору пользователя. Для
текущей задачи достаточно предложить уже выбранной модели прочитать пакет.

## 4. Проверяемая память

```bash
python3 "$ECONOMY" --project "$PROJECT" remember \
  --text 'Verified finding with applicability limits' \
  --evidence 'Specific test, result and source of the conclusion' \
  --source src/example.py --ttl-days 30
python3 "$ECONOMY" --project "$PROJECT" recall 'specific problem'
python3 "$ECONOMY" --project "$PROJECT" inspect NOTE_ID
python3 "$ECONOMY" --project "$PROJECT" pack --task task.json \
  --source src/example.py --query 'specific problem'
```

SQLite FTS5 ищет по тексту и evidence. Хешируется целый связанный файл, поэтому
учитываются незакоммиченные изменения. Пропавшие, изменённые и просроченные
источники исключают запись из поиска. `inspect` показывает причины.
TTL — 1–365 дней (дробные значения допустимы); для внешних фактов без файлов
актуальность ограничивается только TTL и качеством evidence. Инструмент не
перепроверяет внешние сайты и не доказывает истинность заметки.
Дубликат актуальной записи возвращает прежний id. Истёкшую запись можно заново
сохранить только с новым явным действием проверки/записи. Поиск проверяет
не более 200 кандидатов, возвращает до 50; TypeSafe принимает максимум 20.

## 5. TypeSafe: сначала сравнение

[Контракт API](https://docs.typesafe.ai/introduction/quickstart):
POST `https://api.typesafe.ai/v1/systemone`, Bearer `TYPESAFE_API_KEY`,
Choice-вопросы и `answers` с `choice`/`confidence`. SDK не требуется.

```bash
python3 "$ECONOMY" --project "$PROJECT" recall 'specific problem' --preview-remote
# После проверки содержимого и настройки TYPESAFE_API_KEY вне репозитория:
python3 "$ECONOMY" --project "$PROJECT" recall 'specific problem' \
  --typesafe shadow --allow-remote --daily-calls 10
```

Удалённо уходят query, текст и evidence выбранных записей; код файлов, локальные
пути и база не отправляются автоматически. Текст заметок всё равно может содержать
конфиденциальные сведения: просматривайте payload. Проверка известных форматов
секретов — дополнительная эвристика, не гарантия обезличивания.

- `off` — без сети; `shadow` — оценки без изменения порядка; `active` — ранжирование.
- Максимум один запрос за вызов, до 24 KB, тайм-аут 10 секунд; повторов нет.
- По умолчанию максимум 10 запросов за скользящие 24 часа на память проекта.
  Неудачные запросы тоже расходуют локальный бюджет. Это лимит запросов, не USD
  и не общий лимит аккаунта для всех проектов. Расходы провайдера проверяются отдельно.
- Кеш на час по версии вопросов, модели и полному payload. `jev-latest` может
  измениться у провайдера; для воспроизводимого пилота укажите фиксированную
  доступную версию через `--typesafe-model`. Ответ сохраняет resolved model и usage.
- Нет ключа, исчерпан лимит, ошибка API/ответа — локальный порядок с явным статусом.
- Хотя бы одна uncertain-оценка или confidence ниже порога сохраняет локальный
  порядок целиком. Active не удаляет записи: порядок влияет на попадание в бюджет.
- Неверные параметры, слишком большой payload и признаки секретов блокируют
  вызов с ошибкой. Перенаправления HTTP не разрешены.

Порог 0.8 — стартовое значение, не подтверждённая точность. Перед active разметьте
релевантные записи для задач на русском и английском, сравните полноту отбора
в финальном пакете. TypeSafe не пишет резюме, не хранит нашу проектную память
и не заменяет проверку свежести по хешам.

## 6. Навык и профили

Опциональный навык находится в `skill/`; его можно подключить ссылкой из каталога
проектных навыков поддерживаемого клиента. Wrapper разрешает реальный checkout.
Копирование только skill/ без соседнего кода не поддерживается. Каталог навыков
сервера, registry и глобальные ссылки эта поставка не изменяет.

Переиспользуются существующие `codex-context minimal|code|web|...` и `codex-run`.
В новой поставке `minimal` выбирает отдельный V2-профиль с нулевым MCP allowlist.
Старый серверный wrapper до явной миграции сохраняет прежнее поведение.
Проверяйте реально загруженные возможности в клиенте; установка всех skills не
означает загрузку их полных текстов. Модель не переключается автоматически.
См. [миграцию и проверку](REPRODUCIBILITY.md).
API prompt caching оценивайте отдельно: этот CLI не управляет кешем провайдера.

## 7. Приёмочный пилот

Проведите варианты baseline/local/typesafe на одной версии проекта и одинаковых
условиях. Начальный набор из 12 задач: простой поиск символа; небольшое исправление;
изменение двух файлов; падение теста; падение сборки; ревью diff; повтор ранее
решённой ошибки; смена связанного файла; исчезновение файла; конфликт старого
решения с новым требованием; русскоязычный поиск; англоязычный поиск.
Для каждого задания заранее зафиксируйте ожидаемые источники и критерии готовности.

Сохраняйте модель, effort, speed, состояние кеша и исходную ревизию. Учитывайте
подготовку, неудачные попытки и оплату TypeSafe. Повторите сопоставимые прогоны,
поскольку единичный результат зависит от вариативности модели.
Условия принятия: меньше измеренный расход на завершённую задачу при сохранении
качества; нет пропусков обязательных ограничений; TypeSafe улучшает отбор сверх
локального поиска. До измерений проценты экономии и увеличение лимита не заявляются.

## Проверки и откат

```bash
python3 -B -m unittest discover -s tests -p test_context_economy.py
make verify
```

Тесты используют временные проекты, искусственные ответы API и не вызывают модели.
Живые качество, задержка, биллинг и экономия TypeSafe требуют отдельного пилота.
Для отката перестаньте вызывать CLI/отключите опциональную ссылку навыка. Локальные
данные остаются на месте; глобальные hooks и работающий сервер не менялись.
