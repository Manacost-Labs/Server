Статус новой поставки, миграция профилей, новый estimator и границы доказательств:
[REPRODUCIBILITY.md](REPRODUCIBILITY.md). Старые числа и live-примеры ниже относятся
к указанным историческим проверкам; они не доказывают экономию текущей подписки.

2026-09-21. Дополнение к [JEV/Gemma assist](REMOTE-ASSIST.md) и
[пилоту рекомендаций](ADVISORY-PILOT.md). Все команды доступны через

## 1. Автоматические измерения внутри выбранного интервала

Агент начинает измерение один раз перед ограниченной задачей и завершает после
проверок. Не нужны фоновый демон, обход всех сессий или передача журнала в LLM.
Нужен точный путь текущей сессии, полученный из контекста клиента; не выбирайте
«самый новый» файл другой задачи. Один активный интервал разрешён на проект.

```bash
context-economy --project /path/to/project meter-start \
  --task-id issue-123 --session /exact/path/to/current-rollout.jsonl
context-economy --project /path/to/project meter-snapshot --task-id issue-123
context-economy --project /path/to/project meter-finish --task-id issue-123
```

Из выбранного JSONL сохраняются только накопительные счётчики, модель/effort/speed
(когда клиент их сообщает), число событий вызовов инструментов и позиция чтения.
Тексты сообщений, аргументы инструментов и ответы не копируются в базу метрик.
Начальный поиск последних счётчиков ограничен хвостом 8 MiB, последующее чтение
идёт с сохранённой позиции, до 8 MiB за snapshot. Частично записанное событие
переносится на следующий snapshot. Symlink, чужой владелец, подмена и усечение
журнала отклоняются. Для долгой задачи делайте snapshot на завершении фазы.

Автоматически учитываются instrumented OpenRouter-запросы JEV/Gemma в этом
проекте: реальные цены, ошибки с неизвестной ценой и бесплатные попадания в кэш.
`gate` добавляет длительности команд и их неуспешные завершения. Это не счётчик
всех процессов сервера и не общий биллинг ключа OpenRouter.

Счётчики клиента могут отставать от текущего хода; другая работа в этой же сессии
попадёт в тот же интервал. Без новой записи usage разница неизвестна, а не ноль.
При сбросе cumulative counters токены интервала остаются null. Cached/reasoning
не прибавляются повторно к input/output. `helper_api_cost_usd` — цена вызовов
помощников, `api_cost_usd` всей задачи и `codex_credits` автоматически не угадываются.
Повторный finish идемпотентен и не добавляет следующую работу.

```bash
context-economy --project /path/to/project pilot-record \
  --file outcome.json --meter-task issue-123
```

Существующий outcome из ADVISORY-PILOT.md задаёт advice_id, case_id, категорию
выборки, variant, принятие по критериям, проверки, известные регрессии, попытки,
переделки и доказательства. Отсутствующие числовые метрики заполняются из
завершённого интервала; известная единственная модель и effort тоже подставляются.
Явный конфликт с наблюдаемой моделью отклоняется. Смешанные модели требуют
отдельных фаз или существующего `record`/`report --end-to-end`. Метрики не заменяют
подтверждение качества. Helper API cost нельзя выдавать за весь расход задачи.

Если журнал утрачен/усечён, `meter-cancel --task-id issue-123` закрывает неполный
интервал для диагностики; импортировать его как итог пилота нельзя.

## 2. Обязательные факты после сжатия

Перед удалённой обработкой агент/пользователь выделяет существенные контракты и
условия ошибок. Факты задаются точными цитатами выбранных фрагментов, например:

```json
[
  {"source": "src/service.py:20:60", "quote": "return 503"},
  {"source": "docs/api.md:10:30", "quote": "All mutations require authentication."}
]
```

```bash
context-economy --project /path/to/project assist --task task.json \
  --source src/service.py:20:60 --source docs/api.md:10:30 --facts facts.json \
  --provider gemma --mode active --allow-remote --daily-budget-usd 1
```

До API-вызова проверяются структура, происхождение цитат и присутствие важных
источников в локальном fallback-пакете. Файл facts.json не отправляется отдельно.
Если точной цитаты нет в цитатах Gemma, возвращается весь соответствующий выбранный
исходный фрагмент. Непроверенная интерпретация модели не считается сохранённым
фактом. Проверки бюджета и свежести действуют после восстановления, включая
хеш facts.json. При переполнении/ошибке возвращается безопасный локальный пакет.
Результат сообщает `restored_critical_sources` в приватном отчёте assist.

Цель, критерии, ограничения и обязательные инструкции уже сохраняются verbatim.
Этот механизм гарантирует присутствие явно выбранных строк, а не полноту смысла
или автоматическое обнаружение всех важных фактов. Выбирайте достаточно полную
цитату условия, а не отдельный неоднозначный токен.

## 3. Кэш справок по версиям файлов

```bash
context-economy --project /path/to/project brief \
  --source src/service.py:20:60 --source docs/api.md:10:30 \
  --purpose documentation --preview-remote
context-economy --project /path/to/project brief \
  --source src/service.py:20:60 --source docs/api.md:10:30 \
  --purpose documentation --allow-remote --daily-budget-usd 1
```

1–6 явно выбранных фрагментов, суммарно до 24 KB. Gemma получает нейтральное
задание на справку о фактах/контрактах, без истории или цели конкретной задачи.
Ключ кэша включает проект, путь/диапазон, хеш полного файла, purpose, модель и
версию запроса. Справка живёт до 30 дней; изменённый файл обновляется отдельно,
неизменённые используют кэш. Перед выдачей снова проверяются цитаты и хеши.
Часовой кэш транспорта и общий лимит $1/24 часа сохраняются.
Файлы AGENTS.md, CLAUDE.md и SKILL.md не принимаются для сжатия: инструкции
следует передавать целиком через обязательный контекст.

По умолчанию новые API-запросы выключены: существующая проверенная по цитатам
справка читается из кэша, иначе выдаётся локальный исходник в пределах бюджета.
Preview показывает точные тела возможных запросов без сети и ключей. Не загружайте
одновременно справку и весь исходник без причины. Справки — непроверенные
интерпретации с проверенными цитатами, не verified memory. Применимость к новой
задаче оценивается отдельно; нужные критические условия проверяются по оригиналу.

## 4. Пакет по изменяемой функции через Probe

```bash
context-economy --project /path/to/project focus --task task.json \
  --source src/service.py:20:60 --search-in src/service \
  --search-in tests/service --query 'readiness OR worker_ready' \
  --budget 6000 > focused-context.json
```

`--source` указывает 1–6 изменяемых фрагментов; они и найденные ancestor AGENTS.md
обязательны и не обрезаются. `--search-in` ограничивает поиск выбранными файлами
или узкими каталогами кода/тестов: максимум 100 файлов, 200 каталогов и 2 MiB.
Корень проекта целиком не принимается; dot/vendor/build/backup каталоги и symlinks
исключаются. Бинарные файлы, секретные пути и выход из проекта не допускаются.

Probe получает временные копии только разрешённых исходников. Включён поиск
тестов, выдача ограничена 8 совпадениями/1500 токенами/6000 байтами, timeout 20 s.
Без --query инструмент берёт до 12 имён определений/вызовов из выбранного кода;
для сложного синтаксиса задайте запрос явно. Результаты перечитываются по
допустимым путям/строкам и проверяются по хешам; всё проходит общий budget.
Совпадения, перекрывающие уже включённый фрагмент, пропускаются: изменяемая
функция не передаётся повторно внутри более широкого блока.

Stdout — готовый пакет; stderr — статус и список кандидатных источников.
При недоступном Probe остаются обязательные исходники/инструкции. Это поиск
кандидатов в зависимости и тесты, не доказательство полноты call graph.
Если данных не хватает, расширяйте выбранные пути осмысленно. Перед передачей
старшей модели сохраняются действующие ручной gate и `context-budget`.

## 5. Подсказки о повторах

```bash
context-economy --project /path/to/project read --source src/service.py:20:60
context-economy --project /path/to/project gate --watch-source src/service.py \
  --hypothesis 'The null branch is not covered' -- python3 -m unittest tests.test_service
```

Повторное `read` того же диапазона и хеша в течение часа даёт подсказку.
Повторная неуспешная `gate`-команда с тем же диагностическим образцом,
наблюдаемыми версиями входов и гипотезой тоже даёт подсказку. Новая гипотеза,
версия источника или активная измеряемая задача разделяют наблюдения. Вне
измеряемой задачи окно общее для проекта. В таблице повторов — только хеши,
типы событий и время; исходные аргументы и гипотезы туда не копируются.

Подсказка не подавляет вывод, не отменяет выполнение и не меняет exit code.
Полный приватный лог gate остаётся доступным. Это наблюдение над командами
`read`/`gate`, а не перехват всех shell/MCP-вызовов. Меняющиеся логи могут не
совпасть; одинаковая ошибка иногда оправдывает повторную проверку. Учитывайте
контекст, не заменяйте диагностику автоматической сменой модели.

## Проверки и установка

Тесты `test_economy_five.py` включены в `make verify`; тестируются сброс/задержка
usage, частичная JSONL-запись, смена модели и файлов, исходные факты, кэш/расходы,
ограниченный Probe/fallback и повторы без подавления результатов.
При обновлении сохраняется предыдущий runtime. Откат — вернуть предыдущий
symlink `~/.local/share/codex-context-economy/current`; новые SQLite-таблицы
аддитивны и старым runtime не используются. Ключи, приложения и ai-memory
не переустанавливаются. Измеренная экономия подписки пока не установлена.

Живые проверки 2026-09-21 на синтетическом коде: Probe нашёл связанный тест,
после удаления пересекающихся совпадений оценка пакета снизилась с 1841 до 342
токенов. Gemma сохранила обязательное условие `return 200 if worker_ready else 503`;
оценка assist-пакета снизилась с 1679 до 511. Обе оценки — UTF-8 bytes/3,
не биллинговые токены. Справка стоила $0.000069986, assist — $0.000079256,
повтор справки из файлового кэша — $0. Интервал измерения прочитал счётчики
выбранной текущей сессии и отдельно учёл один запрос справки, попадание в кэш
и два ожидаемых сбоя тестовой команды. Эти результаты не записаны как
успешные реальные задачи пилота и не доказывают экономию подписки.
