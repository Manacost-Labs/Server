# JEV + Gemma через OpenRouter

Реализовано 2026-09-21. Подготовка ограниченного контекста и черновиков памяти,
документации или замечаний к коду. Это отдельная команда перед основной моделью;
она не проксирует авторизацию Codex, не меняет выбранную модель/effort, не
перезаписывает историю и не устанавливает сторонние hooks компактации.

## Запуск

Работает установленная команда `context-economy`:

```sh
# task.json: goal, criteria (непустой список), constraints (список).
context-economy --project /path/to/repo assist \
  --task task.json --source docs/design.md:10:80 --required contract.md \
  --purpose documentation --provider cascade --preview-remote

# Только при разрешённых данных и бюджете. По умолчанию исходный пакет сохраняется.
context-economy --project /path/to/repo assist \
  --task task.json --source docs/design.md:10:80 --required contract.md \
  --purpose documentation --provider cascade --mode shadow \
  --allow-remote --daily-budget-usd 1 > /tmp/context-packet.json
```

Без `--allow-remote` возвращается только локальный пакет, даже при наличии ключа.
`--preview-remote` показывает конкретные тела возможных запросов и endpoints,
без ключа и сетевых вызовов. Оба каскадных запроса используют тот же заранее
выбранный state; JEV не добавляет скрытые данные в запрос Gemma.

- `--provider jev`: оценки релевантности и ранжирование; без генерации справки.
- `--provider gemma`: точные цитаты плюс непроверенная интерпретация и uncertainties.
- `--provider cascade`: оба результата. Выполняется не более двух HTTP-запросов,
  без автоматических повторов. Если первый этап не прошёл, второй не запускается.
- `--purpose context|memory|documentation|review`: назначение черновика. `review`
  даёт вспомогательные замечания, не утверждает корректность и не заменяет тесты.
- `--mode shadow`: stdout сохраняет исходный пакет. Кандидат и оценки — в отчёте.
- `--mode active`: использует проверенный по происхождению кандидат. При отсутствии
  уменьшения размера Gemma-пакета возвращается локальный оригинал.

Stdout содержит один пакет, stderr — короткий статус и путь к приватному JSON
отчёту. Не загружать оба полных пакета в модель при обычной работе: это уничтожит
экономию. В отчёте есть расходы, размеры и оценки; размеры — эвристика bytes/3,
не токены модели и не расход квоты. Для пакета можно дополнительно вызвать
`context-budget --limit 12000 /tmp/context-packet.json`.

## Контракты и сохранность контекста

Передавать 1–12 явно выбранных необязательных фрагментов, максимум 24 KB суммарного
state вместе с задачей. Пути/хэши файлов остаются в локальном индексе; удалённая
модель получает идентификаторы и текст. Текст задачи также передаётся. Существуют
эвристическая проверка секретов и запрет чувствительных путей; они не гарантируют
обнаружение каждого секрета. Выбирать только разрешённые для обработки материалы.

AGENTS.md вдоль выбранных путей и `--required` сохраняются целиком локально и
исключаются из модельного пересказа. Системные/клиентские/родительские инструкции
по-прежнему остаются ответственностью активного агента. Удалённым этапам не
передаются переписки, файлы окружения или история инструментов автоматически.

JEV может изменить порядок только при отсутствии uncertain и confidence >=0.8
у всех оценок. Он не удаляет источники. Gemma должна сослаться на каждый выбранный
необязательный источник; каждая quote проверяется как точная непустая подстрока.
Хэши задачи, обязательных и необязательных источников повторно проверяются после
вызовов. Если источник изменился — команда завершается ошибкой без устаревшего
пакета. Неверный ответ, недоступный провайдер или исчерпанный бюджет дают исходный
локальный пакет; статус fallback виден отдельно.

Проверка цитаты доказывает происхождение текста, не правильность интерпретации
или полноту выбранного отрывка. `draft_note` и предлагаемые заметки памяти нельзя
автоматически записывать как verified. После независимой проверки использовать
обычный `remember --text ... --evidence ... --source ...`.

## Один ключ, два разных API

Ключ берётся из `OPENROUTER_API_KEY` или из
`~/.config/codex-context-economy/remote.env` (владелец — текущий пользователь,
права 0600, обычный файл без симлинка). Файл не исполняется как shell.
Отдельный TypeSafe key для `assist` не нужен. Старые параметры `recall --typesafe`
и `pack --typesafe` пока относятся к прямому TypeSafe-адаптеру и остаются off.

| Роль | Model ID | Endpoint |
| --- | --- | --- |
| JEV | `typesafe/jev-1.13` | `https://openrouter.ai/api/alpha/decisions` |
| Gemma | `google/gemma-4-26b-a4b-it` | `https://openrouter.ai/api/v1/chat/completions` |

JEV имеет modality `text->decisions`, поэтому отсутствует в стандартной текстовой
выдаче `/api/v1/models`. Проверять `/api/v1/models?output_modalities=all`.
Это не chat-completions модель. Контракт Decisions проверен по официальному
[Python SDK](https://github.com/OpenRouterTeam/python-sdk/blob/main/src/openrouter/decisions.py).

В запросах стоят price caps: JEV $0.042/M input и $0 output; Gemma $0.09/M input
и $0.30/M output; фиксированная плата за запрос запрещена. Используются
`data_collection=deny`, запрет fallback-провайдера, запрет HTTP redirects и
отключение унаследованных прокси. Для Gemma обязательна поддержка параметров.
Отсутствие подходящего маршрута не снимает ограничения, а даёт локальный fallback.
Источник: [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection).

Общий для всех проектов реестр `remote_reservations` хранится в приватной SQLite
context-economy для домашней директории. `--state-dir` команды не сбрасывает этот
реестр. Максимум пилота — $1 за скользящие 24 часа; меньший лимит можно задать
аргументом. Резервируется $0.003 перед JEV и $0.025 перед Gemma: консервативные
оценки по максимальному контексту и ценовым ограничениям. При известном usage.cost
сохраняется сумма провайдера; при ошибке/неизвестной сумме резерв остаётся занятым.
Это предохранитель клиента, не гарантия счёта сторонней платформы. Он относится
к `assist`, а не к другим приложениям, использующим тот же ключ.

Валидированные ответы кэшируются на час отдельно по проектам; повторный cache hit
не вызывает API и не создаёт новый резерв. Исходный receipt в cache-отчёте не
означает повторную оплату. Отчёты и кэш могут содержать выбранные материалы;
автоматическое удаление не выполняется.

## Рассмотренные проекты

Все три репозитория на дату проверки имеют MIT; код не копировался и их
установщики не выполнялись.

- [jev-codex-router](https://github.com/0xNatoshi/jev-codex-router): выбор модели
  и effort на каждом обращении, отдельное состояние для JEV и полный контекст
  исполнения. Полезные идеи — ограниченный вход и сохранение работоспособности
  при ошибке. Заявленные исторические -60% относятся к симуляции старой политики,
  не измеренной квоте. Маршрутизация моделей не включена в наш пилот.
- [jev-review](https://github.com/NiazMorshed2007/jev-review): отдельные оценки
  качества по рубрикам; Jev не объясняет причины свободным текстом. Может быть
  отдельным дополнением позже, но непрерывный MCP-review дублировал бы работу.
  Наш purpose=review не реализует и не заявляет эквивалент его полной системе метрик.
- [fast-jev-compaction](https://github.com/tamaratran/fast-jev-compaction):
  библиотека и plugin Claude Code для удаления/сокращения tool-call/result пар,
  с закреплёнными недавними сообщениями. Полная история повторяется в батчах JEV;
  выборочное удаление также теряет информацию. Это не готовая замена компактации
  Codex. Наш адаптер работает только с явно выбранными источниками вне истории.

## Проверка

16 регрессионных тестов: приватный ключ, shared budget, неизвестные
расходы, отсутствие платных вызовов по умолчанию, точность/полнота ссылок,
исключение обязательных инструкций, устаревание, кэш и разделение stdout/report.
Полный вход — `make verify`.

Публичный синтетический shadow-пилот 2026-09-21: оба API вернули валидные ответы;
три требуемых факта проверены в цитатах. Зарегистрировано $0.000212306 за два
запроса. Локальная эвристика пакета: 2864 → 642. Это тест работоспособности и
пример уменьшения пакета, не доказательство экономии подписки или качества
на реальных изменениях трёх проектов.

## Отключение

Убрать `--allow-remote` либо прекратить использовать assist: остальные команды
и сервис ai-memory продолжают работать. Не удалять ключи, базы и отчёты при
откате. Для отката runtime вернуть прежнюю ссылку `current`; установленные
модельные настройки Codex и сервер приложений эта интеграция не меняет.
