# Воспроизводимая настройка и доказательства

Эта поставка подготовлена в изолированной рабочей копии. Она не устанавливает
ничего при импорте, тестировании или `make verify`, не меняет рабочий серверный
config и не выполняет push/deployment. Все интеграционные тесты используют
временный `CODEX_HOME`. Более ранние инструкции и серверные receipts описывают
предыдущую установленную версию, а не автоматический rollout этой поставки.

## Совместимость

Проверенный CLI: **codex-cli 0.153.0**, Python **3.11+**, Linux, Bash/readlink.
Установщик требует эту версию CLI и наличие V2-профилей в `codex --help`.
Другие версии явно отклоняются до отдельной проверки и обновления pin.
Это pin совместимости, а не утверждение, что будущие версии не поддерживаются.

Проверка без модели и авторизации:

- `codex app-server --strict-config` с EOF проверяет поля базового TOML;
- `codex -p PROFILE mcp list --json` проверяет фактическое слияние профиля;
- профиль ограничен таблицами MCP и optional plugins с булевым `enabled`; дополнительные настройки
  профиля отклоняются, а настройки модели остаются в базе/явном выборе оператора.

В этой версии `app-server` не принимает `-p`, а `mcp` не принимает
`--strict-config`: эти проверки нельзя слить в одну вымышленную команду.
Публичная [JSON schema](https://developers.openai.com/codex/config-schema.json)
может описывать другую версию профилей; локально проверенный CLI — основание pin.
Справка: [configuration reference](https://developers.openai.com/codex/config-reference).

## Профили

База выключает все объявленные MCP. Каждый `<name>.config.toml` перечисляет
все переключатели явно; `minimal` больше не обходит выбор профиля.

| Профиль | Включённые MCP | Остальные инструменты |
|---|---|---|
| minimal | нет | shell, rg/RTK при наличии |
| code | codegraph | локальные файлы/тесты; Probe по необходимости |
| web | chrome-devtools | браузер через установленный `chrome-devtools-mcp` |
| research | context7, openaiDeveloperDocs | источники документации |
| github | github | установленный `github-mcp-server stdio`, отдельная авторизация |
| infra | cloudflare, ovhcloud | отдельная авторизация провайдеров |
| typeui | `typeui`, если включён установленный плагин | TypeUI skill/plugin по требованию |

При миграции существующего typeui-профиля сохраняйте его `[plugins]` enabled
переключатели, включая `typeui@bergside`. Launcher разрешает только булевый
`enabled` для плагинов; настройки исполнения и другие поля остаются вне профиля.
Этот установленный плагин добавляет сервер `typeui` самостоятельно. Он разрешён
только для typeui-профиля с enabled=true; minimal исключения не получает.
В изолированном CODEX_HOME без установленного плагина проверяется конфигурация,
но перед запуском launcher требует появления его MCP. Поэтому перенос также
нуждается в проверке фактического списка MCP в целевом окружении.

Установщик проверяет доступность локальных команд включаемых MCP, сообщает
недостающие optional tools, но не скачивает их и не проверяет авторизацию
сетевыми запросами. Launcher отклоняет профиль с отсутствующей командой.
Работа и версия самого внешнего MCP, браузера и провайдерской авторизации
проверяются отдельно оператором перед использованием соответствующего профиля.
Новый неизвестный включённый MCP в базе вызывает ошибку allowlist, даже для minimal.

`codex-context` не создаёт профили на лету. Отсутствующий файл, неизвестная версия,
несовместимый формат и конфликтующий override дают ошибку до запуска модели.
Прямой запуск Codex и более высокие настройки клиента находятся вне этой гарантии.
Рабочую модель текущей desktop-задачи launcher не меняет.

## Установка только явной командой

Запускать из каталога `integrations/codex/subscription-savings`:

```bash
python3 codex_setup.py --dry-run --codex-home /ABSOLUTE/NEW/CODEX_HOME
python3 codex_setup.py --install --codex-home /ABSOLUTE/NEW/CODEX_HOME
python3 codex_setup.py --verify --codex-home /ABSOLUTE/NEW/CODEX_HOME
```

`--dry-run` не создаёт/меняет целевой каталог. Проверки CLI работают только
временной копией, поэтому не создают служебные файлы в пользовательском home.
Установка пишет только config, семь профилей, manifest и резервную копию.
В existing home без manifest неизвестные файлы конфигурации не принимаются
даже если выглядят похожими. Ручное изменение управляемого файла также вызывает
отказ; автоматического merge пользовательской конфигурации нет.

Повторная идентичная установка возвращает `unchanged`. При разрешённом обновлении
управляемой поставки все заменяемые файлы сохраняются в `economy-backup-*` с
`restore.json`; используются временные файлы, атомарная замена и rollback при
ошибке записи. Прерывание питания между файлами обнаруживается checksum-проверкой
на следующем запуске; это не транзакционная файловая система.

Не копируйте auth.json, secrets или trust hashes между homes. Авторизацию и
команды hooks оператор проверяет локально, включая `/hooks`. Установщик не
объявляет команды доверенными. Optional compact-plus устанавливается отдельно;
без него wrapper возвращает успешный пропуск и не блокирует задачу.

Держите bin вместе с Python-модулями и profiles. Можно добавить этот bin в PATH
или сделать symlink на wrappers. Копирование одиночных wrappers больше не работает.
Старый неизвестный server config мигрируется вручную после сравнения с примером;
не следует удалять его ради прохождения installer.

## Подсчёт бюджета

`context-budget --model MODEL --limit 12000 FILE...` выдаёт JSON:
model, method, tokenizer, tokenizer_tokens, estimated_tokens, margin,
actual_codex_tokens=null, limit, exceeded. Exit 3 означает превышение.

Для точных известных идентификаторов GPT-4o/GPT-4/GPT-3.5-turbo используется
соответствующий encoding пакета tiktoken, если он доступен. Никакого guessing
по префиксу `gpt-5`/`gpt-6` нет. Для остальных моделей и при отсутствии tokenizer:
**число UTF-8 байт + 15%**, с округлением вверх. Запас можно увеличить.
Это намеренно консервативная оценка, а не доказанная верхняя граница неизвестного
tokenizer. Она учитывает кириллицу, Unicode, код и JSON; скрытые инструкции,
история и framing модели сюда не входят.

Внутренний pack использует тот же консервативный fallback. Часть пакетов,
проходивших старую эвристику bytes/3, теперь потребует сужения. Не поднимайте
лимит автоматически ради старых результатов. `meter` продолжает отдельно
выдавать реальные зарегистрированные счётчики; это другой источник данных.

## Compaction: затраты отдельно от пользы

Wrapper не вызывает дополнительную Luna для малых/дешёвых интервалов. Defaults:

- `COMPACT_PLUS_MIN_TRANSCRIPT_BYTES=65536`;
- `COMPACT_PLUS_MIN_UNCACHED_TOKENS=40000`: прирост input−cached+output после
  последней попытки summary в данной сессии. Reasoning не добавляется второй раз.

Требуется точный transcript из текущего CODEX_HOME/sessions. Неизвестный расход,
сброс счётчика, missing plugin/tool, некорректный input или ошибка hook дают
fail-open: основной Codex может продолжить штатную compaction.

После порога optional compact-plus может вызвать Luna/low. Отдельный backend
читает JSONL usage этого вызова, пишет только счётчики/статус/время в
`CODEX_HOME/economy-metrics/compaction.jsonl`. Отсутствующие поля и стоимость USD
остаются null. Внешний API этим wrapper не вызывается. Такие вызовы всё равно
могут расходовать подписку Codex. Prompt/summary/сырые события в журнал метрик
не записываются. Не суммируйте включённые друг в друга поля токенов.

1200 tokens — настройка/инструкция compact-plus, а не гарантированный лимит
генерации CLI. Ответ сверх 12000 UTF-8 bytes отвергается; это не возвращает уже
потраченные токены. Защита от повторной попытки не доказывает качество summary.
Новый механизм не заменяет native compaction и не доказал уменьшение квоты.

## Benchmark

Скопируйте `benchmark/baseline.template.json` и `economy.template.json` вне
репозитория и заполните наблюдаемыми данными. Templates намеренно не являются
готовыми результатами: исходный commit требует подстановки, метрики — null.

```bash
python3 benchmark.py --baseline /path/baseline.json --economy /path/economy.json
```

Обязательны одинаковые задача, starting commit, репозиторий, модель, effort,
скорость, критерии качества и команда проверок. Смена модели — отдельный
эксперимент, не прямая пара для эффекта контекстной оптимизации. dataset real и
synthetic не смешиваются. Пропущенные показатели дают incomplete; оценки нельзя
выдавать за observed. Считать весь цикл, включая подготовку, дополнительные
запуски моделей, compaction, API, проверки, retries и переделки.

Вывод — абсолютные разности economy−baseline, статус сопоставимости и результат
критериев качества; процент подписочной экономии всегда null. Негативные исходы
сохраняются. Самооценка JEV не заменяет проверку результата. Парные результаты
реальных задач в этой поставке отсутствуют.

## Проверки и матрица доказательств

```bash
python3 -B -m unittest discover -s tests -p test_codex_setup_e2e.py
make verify
```

Запускать из корня репозитория. Offline E2E проверяет процессы wrappers с
поддельным Codex, без API. Если настоящий Codex установлен, отдельный тест
проверяет его parser/merge всех семи профилей без модели и авторизации.
Отсутствие CLI обозначается skip этой проверки, а не доказанной совместимостью.
Остальные offline tests при этом выполняются. Полные live задачи, dispatch hooks
после локального trust и провайдерские MCP требуют отдельного operator smoke;
они не запускаются обычным CI и не выдаются за результаты offline suite.

| Механизм | Что проверяется | Что ещё не доказано |
|---|---|---|
| Постоянные инструкции | 8870 → 3986 bytes, cap 4500 в CI; детали сохранены отдельно | Фактическое снижение квоты клиента |
| Profiles/install | allowlists, отсутствие перезаписи, повторный запуск, parser CLI | Работа всех optional MCP с авторизацией |
| ObservationPack | вызов настроенного handler и точный recall Unicode | Качество задач/квота от уменьшения вывода |
| Budget | маркировка метода, запас, oversized exit, неизвестные модели | Точное число токенов GPT-5.6/GPT-6 |
| Compaction guard | порог, пропуски, счётчики auxiliary, fail-open | Чистая экономия и качество реальных summaries |
| Benchmark | проверка сопоставимости и неполных данных | Реальная парная выборка |
| JEV/Gemma, memory, focus | ранее реализованы; сохранены прежние проверки | Общая экономия подписки и качество на трёх проектах |

Рабочая серверная установка этой задачей не обновлялась. Ни наличие исходников,
ни успешные синтетические тесты не означают rollout или реальную экономию.

## Риски и откат

Главные изменения совместимости: V2 files вместо неявного base minimal,
строгий pin CLI, более консервативный бюджет и новый соседний Python runtime.
Старт без нужного optional tool теперь завершается до работы модели.

Для текущей задачи откат — отказаться от изолированной рабочей копии; live
состояние не менялось. После будущей явной установки остановите использующие
её задачи, проверьте `restore.json` выбранной backup и восстановите только
перечисленные config/profile/manifest файлы. Пути, отсутствовавшие до установки,
удаляйте только если они всё ещё совпадают с installed manifest; чужие изменения
не перезаписывайте. Auth, sessions, plugins и проекты в rollback не участвуют.
