# Пилот качества и расхода v2

Цель: проверить уменьшение полного измеренного расхода токенов при сохранении
качества, числа переделок и времени. Результаты не превращаются в процент
экономии подписки. Стоимость OpenRouter учитывается отдельно; токены разных
моделей не имеют одинаковой денежной стоимости.

## Начало измерения

Перед подготовкой задачи выберите точный существующий JSONL её сессии. Не ищите
«самый новый» файл и не используйте сессию другой задачи. Один физический файл
может принадлежать только одному активному измерению в общем хранилище проекта.
Разные сессии одного проекта теперь измеряются параллельно. `--state-dir` создаёт
независимое хранилище: между такими хранилищами общей блокировки сессий нет.

```sh
context-economy --project /path/to/project meter-start --task-id api-001 \
  --session /exact/path/to/session.jsonl --from-task-start
```

`--from-task-start` — утверждение оператора, что подготовка ещё не началась.
Без флага интервал останется частичным даже после последующего подтверждения
полноты. Предыдущие интервалы автоматически не повышаются до полных.

Каждому вспомогательному вызову явно передавайте идентификатор. Флаг верхнего
уровня `--meter-task-id api-001` или переменная `CODEX_ECONOMY_TASK_ID=api-001`
задают привязку только для этого вызова. Неизвестная/завершённая задача отклоняется
до выполнения команды или платного запроса. Без привязки события остаются
нераспределёнными и делают полноту пересекающихся интервалов неопределённой.

```sh
CODEX_ECONOMY_TASK_ID=api-001 context-economy --project /path/to/project \
  brief --source docs.txt --facts critical.json --allow-remote
```

Gemma получает только выбранные фрагменты документации/логов/справок. Пользовательский
запрос и обязательные инструкции сохраняются отдельно. `critical.json` содержит
массив объектов `{"source":"docs.txt","quote":"точная обязательная цитата"}`.
Указывайте существенные ограничения, ошибки, противоречия и оговорки о
неопределённости. Выжимка с пропущенной цитатой заменяется исходным фрагментом.
Автоматической гарантии сохранения всей семантики нет; качество проверяется
критериями задачи. Версионные хеши и оригинальные файлы позволяют проверить вывод.
Исходники короче 600 UTF-8 байт не запускают платную подготовку; уже имеющийся
валидный кеш можно проверить без нового удалённого вызова.

Весь сериализованный пакет, включая ссылки, метаданные, предупреждения и
восстановленные оригиналы, должен сократиться минимум на 15% относительно такого
же пакета с исходниками. Порог `--min-reduction` допустим от 0.05 до 0.9.
`reduction.applied=false` означает возврат к оригиналам. Если оригиналы не помещаются
в заданный бюджет, команда просит сузить источники; молчаливого обрезания нет.
Это локальный прокси размера, а не измерение подписки. Любой дополнительный текст,
который вызывающий код добавляет после результата, нужно учитывать отдельно.

## Помощники, compaction и завершение

Если вспомогательная работа идёт в отдельной сессии Codex, подключите её до начала
работы. Внутренняя compaction, уже включённая в счётчики основной сессии, не
подключается повторно. Вызовы OpenRouter через привязанный CLI учитываются событиями.

```sh
context-economy --project /path/to/project meter-attach --task-id api-001 \
  --session /exact/path/to/helper-session.jsonl --role compaction
context-economy --project /path/to/project meter-snapshot --task-id api-001
context-economy --project /path/to/project meter-finish --task-id api-001 \
  --coverage-evidence 'Укажите артефакты всех фаз, помощников и проверенных счётчиков'
```

Снимок нужен до накопления следующих 8 MiB журнала. Подключение не включает
исторический расход помощника до снимка. Новый пустой журнал имеет нулевой
начальный счётчик; непустой журнал без наблюдаемого счётчика остаётся неизвестным.
Отмена сохраняет историю: `meter-cancel --task-id api-001`.

`input_tokens`, `output_tokens`, `cached_input_tokens`, `reasoning_tokens` включают
основную и явно подключённые сессии Codex. `all_model_*` дополнительно включают
привязанные удалённые вызовы. Кешированный ввод уже входит во ввод, reasoning —
в вывод. Не складывайте подмножества повторно. Неизвестный расход сбойного вызова,
нераспределённые события, сброс счётчиков и события после завершения препятствуют
полному результату. Известные поздние расходы сохраняются в отчёте.

`coverage.status=declared-complete` означает наличие заявления оператора и отсутствие
обнаруженных пробелов. Это не независимое доказательство полноты. Клиентские
счётчики могут запаздывать; завершайте измерение после появления финального
события usage. Не повышайте неполный результат вручную ради прохождения порога.

## Сравнение

Копируйте `baseline.v2.template.json` и `economy.v2.template.json` на каждую реальную
задачу. Заполняйте наблюдаемыми значениями; неизвестное оставляйте `null`.
Для v2 поля токенов охватывают все модели: используйте соответствующие `all_model_*`
поля счётчика. Повторные попытки, запуски моделей и переделки требуют отдельной
фиксации; счётчик их смысл автоматически не определяет. Укажите критерии приёмки,
свидетельства тестов и полноты всех фаз. Синтетические проверки записываются
только с `dataset=synthetic` и не участвуют в оценке реальной эффективности.

Сопоставляйте одинаковую задачу, репозиторий, исходный commit, модель, effort,
скорость, критерии и команду проверки. Не запускайте дублирующий платный baseline
без отдельной необходимости: одиночный результат сохраняется без процента.
Соберите 10–20 задач разных типов для HearthPulse, API и WordPress. Эти результаты
не гарантируют качество всех будущих задач.

Создайте `pairs.json`: массив путей относительно файла манифеста, например
`[{"baseline":"api-001.baseline.json","economy":"api-001.economy.json"}]`.

```sh
python3 ~/.local/share/codex-context-economy/current/benchmark.py --manifest pairs.json
```

Пустой манифест допустим и возвращает `insufficient-evidence`. Не создавайте
фиктивные наблюдения. Старый формат v1 доступен для сравнения отдельных пар,
но не проходит новую оценку полноты. Дубликаты задач отклоняются. Незавершённая
реальная пара не скрывается за десятью удачными результатами.

`pilot-target-met` требует минимум 10 разных реальных полных пар, прохождения
приёмки и тестов обеих версий, отсутствия роста retries/переделок в каждой паре,
медианного сокращения `input_tokens+output_tokens` минимум на 20% и медианного
отношения времени не выше 1. Расход API показывается отдельно. Это предварительный
порог пилота по токенам; денежная экономия и экономия квоты остаются недоказанными.

## Совместимость

Миграция SQLite сохраняет старые интервалы и события, снимая ограничение одной
активной задачи на проект. Старые версии инструмента пытаются восстановить это
ограничение. Перед откатом на такую версию завершите/отмените параллельные интервалы
текущей версией; не удаляйте измерения или базу ради отката.
